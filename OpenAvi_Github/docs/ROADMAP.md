# OpenAvi ロードマップ — AviUtl（拡張編集）機能互換に向けて

> 最終更新: 2026-10-23（段階 A 完了時点）
>
> **目標**: AviUtl 1.10 + 拡張編集 0.92 の機能を、基本すべて OpenAvi（Windows / macOS / Linux）で使えるようにする。

---

## 1. 現状の評価

### 揃っている土台

- **データモデル** (`au2-core`): オブジェクト・エフェクト・トラック・中間点が `.exo` の構造とほぼ 1:1 に対応しており、AviUtl の全機能を表現できる下地がある。
- **ファイル入出力** (`au2-exo`, `au2-aup`): `.exo` / `.aup` / `.aup2` の読み書き、Shift_JIS (CP932) / UTF-8 自動判別、ラウンドトリップ保証。
- **タイムライン UI** (`au2-app`): レイヤー、オブジェクトの追加・分割・削除、中間点の追加、スナップ。
- **マルチプラットフォーム**: Windows / macOS（`.app` パッケージ化済み）/ Linux。

### 段階 A で埋まったもの（2026-10-23 時点）

- **合成エンジン** (`au2-render`): ヘッドレスの GPU 合成。プレビューと書き出しで共用。図形（SDF）・画像・動画・テキスト・色調補正フィルタ。
- **動画の書き出し** (`au2-export`): ffmpeg で MP4（H.264/H.265 + AAC）。バックグラウンド実行・キャンセル可。
- **音声** (`au2-audio`): ffmpeg でデコードし、音量・左右・再生位置・速度・ループをミックスして cpal で再生。
- **動画デコード** (`au2-media`): 動画 1 本につき ffmpeg を常駐させ、固定・可変フレームレートの両方で正しいコマ番号を返す。
- **Undo / Redo**: シーンのスナップショット差分方式（ドラッグ 1 回 = 1 段）。

### まだ不足しているもの

| 項目 | 現状 | 影響 |
|---|---|---|
| **描画の機能** | 標準描画（X/Y/Z・拡大率・透明度・回転）、図形・画像・動画・テキスト（装飾なし）、色調補正のみ | 他のフィルタ・合成モード・クリッピング・3D/カメラ・シーン等が未実装（段階 B・C） |
| **Lua 実行** | スクリプトの設定項目を読み取るだけ | スクリプト資産が動かない（段階 D） |
| **書き出しの設定** | MP4 の既定設定のみ（API は範囲・コーデック・品質に対応済み） | 設定画面が無い |
| **互換性の検証** | 実 AviUtl の出力との比較は未実施 | 見た目の一致度が不明（段階 E） |

## 3. 技術方針

1. **描画エンジン `au2-render`（新規クレート）**
   - wgpu のオフスクリーン描画で、UI から独立させる。
   - パイプライン: オブジェクトを RGBA テクスチャ化 → フィルタチェーン（WGSL シェーダ）→ 標準/拡張描画（3D 変換・カメラ）→ 合成モード・クリッピングでフレームバッファへ合成。
   - **プレビューと書き出しで同じエンジンを使い**、見た目と出力結果の一致を保証する。
   - ヘッドレスで動かせるようにし、参照画像との比較テスト（ゴールデンイメージテスト）を書けるようにする。
2. **常駐デコーダ**
   - 1 フレーム 1 プロセスをやめ、クリップごとに常駐する ffmpeg パイプ、または libav バインディングへ移行する。
   - macOS では VideoToolbox によるハードウェアデコードも検討する。
3. **音声**: `cpal` による出力とミキサー。映像との同期クロックを持つ。
4. **書き出し**: 描画エンジンのフレームと音声ミックスを ffmpeg に渡してエンコードする（H.264 / HEVC / ProRes。macOS では VideoToolbox エンコードも可）。
5. **Lua スクリプト**
   - `mlua` + LuaJIT（AviUtl と同じく Lua 5.1 系）で、`obj` API（`obj.draw` / `obj.effect` / `obj.load` / `obj.getpixel` / `obj.putpixel` / `obj.setoption` など）を再実装する。
   - スクリプトは `obj.effect("ぼかし", ...)` のように標準フィルタを呼ぶため、**標準フィルタの実装が前提**になる。
6. **DLL プラグインは互換を目指さず、役割を内蔵機能で置き換える**
   - 入力プラグイン（L-SMASH Works 等）→ ffmpeg デコード
   - 出力プラグイン（x264guiEx 等）→ 内蔵の書き出し機能
   - Windows 限定の 32bit IPC ブリッジは、必要性が明確になってから検討する。

## 5. 前提と制約

- **ピクセル単位の完全一致は困難**: 拡張編集はクローズドソースで、フィルタの丸め・アルゴリズムは非公開。「見た目が同等」を目標とし、Windows 機の実 AviUtl で書き出した参照画像と比較して検証する。
- **DLL 依存スクリプトは動かない**: `rikky_module.dll` などの DLL を同梱するスクリプトは macOS / Linux では動作しない。Lua のみで書かれたスクリプトは対象とする。
- **Windows プロジェクトの持ち込み**:
  - フォント: 「MS UI Gothic」など macOS に無いフォントの代替マッピングが必要。
  - パス: `C:\...` 形式のメディア参照を付け替える（リンク切れ素材の再指定）画面が必要。
- **ライセンス**: AviUtl 本体の挙動を観察して再実装することは問題ないが、本体の逆アセンブル結果は使わない。ユーザー製スクリプトはそれぞれのライセンスに従い、同梱しない。
- **互換の基準**: まず「AviUtl 1.10 + 拡張編集 0.92」を基準とする（スクリプト資産が最も多いため）。`.aup2`（AviUtl2）の読み書きは維持する。

## 6. 既知の制限（段階 A 時点・意図して後回しにしているもの）

- 音声のデコードは初回再生時に UI スレッドで行う（長いファイルでは一瞬止まる）。再生中の編集（音量・移動）は次の鳴らし直しまで聞こえない。
  音声は 30 秒ずつミックスし、窓の終わりで鳴らし直す（継ぎ目に小さな隙間が出る場合がある）。映像との同期は開始時刻を揃えるだけ。
- Undo は文字入力など 1 キーごとに 1 段になる（ドラッグは 1 段）。Undo で保存時点に戻っても「未保存」表示は消えない。
- アニメーション GIF を「画像ファイル」として置くと、最初に取得されたフレームで止まる（動画としては巡回する）。
- アイドル時も UI 再描画のたびにプレビューを描き直す（再描画の抑制は未実装）。
- 書き出し: コーデック・範囲・品質の選択 UI が無い（API は対応済み）。ハードウェアエンコード（VideoToolbox 等）は未対応。
- GL バックエンド（Vulkan の無い Linux・VM）でのプレビューは未検証。Windows は未検証。
- 同じ動画ファイルを別々の再生位置で同時に表示する（ピクチャ・イン・ピクチャ等）と、ファイル 1 本につき常駐デコーダ 1 本のため、
  後戻りのたびに ffmpeg を起動し直す。
- メモリ: 動画のデコード済みフレームは 1 本あたり 256MB まで（全体の上限は無い）。音声のデコード結果は破棄しない。
- GPU や ffmpeg が無い環境では、該当テストが「スキップ」として成功扱いになる（CI で何も検証されない可能性がある）。
- macOS では Metal の検証レイヤーを付けてテストする: `MTL_DEBUG_LAYER=1 cargo test -p au2-render`（解放済みオブジェクト参照などを検出できる）。
- 音声出力は f32 サンプルのストリームだけを開く（f32 非対応の ALSA デバイスでは鳴らず、警告ログのみ）。
- 映像ストリームが長さを持たない形式（MKV/WebM）では、終端越えの要求を初めて受けたときに ffprobe で映像パケットを走査してフレーム数を調べる
  （長い動画では 1 回だけ数百ミリ秒〜数秒止まる）。ffprobe が無いと、終端越えの位置は最後のフレームを取得できる範囲でのみ表示できる。
- `VideoStream` は返すフレームを 1 回複製する（保持用。4K では目立つコスト）。
- 終端越えの判定（`past_end`）は動画 1 本ごとに一度決めたら覚え続ける。ファイルが途中で差し替わる・一時的に読めない場合は、再読み込み（新規プロジェクト等）まで終端以降が最後のフレームのままになる。
- 30fps の動画を 60fps のプロジェクトで表示すると、同じ動画フレームでもテクスチャを毎フレームアップロードし直す（キーが時刻ベースのため。表示は正しい）。
  画面に同時に 16 本を超える動画を出すとテクスチャのキャッシュが入れ替わり続ける。
- 動画の「ループ再生」は、映像の長さが分かる場合（ffprobe で取得できた、または終端まで再生して学習できた場合）のみ巻き戻す。
- 可変フレームレート（VFR）動画（画面録画など。静止区間でフレームが出力されない）も正しいコマ番号で表示する。全動画を
  `-noaccurate_seek -copyts` + `fps`（枠は半フレームずらして時刻のゆらぎに強くする）+ `trim` で起動する。
  MKV/WebM は ffprobe が平均レートしか返さないので、先頭 500 パケットの時刻から本来のレートを推定する（録画の冒頭が長い静止だと推定できない）。
  順再生で終端まで読み切って学習した長さは、fps フィルタが最後のフレームを 1 枚複製するため最大 1 フレーム長い。
  1 枚だけの個別デコード（フォールバック）は、VFR の静止区間では通常のシークと同じくずれる場合がある。開始時刻が 0 でない VFR ファイル（MPEG-TS 等）は未検証。
- シークは目的の 2 秒手前から読み始める（MPEG-TS などで直後のキーフレームに着地しても番号がずれないため）。
  キーフレーム間隔が 2 秒を超える TS では、シーク直後の最大 1 GOP 分が次のキーフレームの絵になる。
- AVI に入った B フレーム付きの H.264 / MPEG-4（AviUtl では稀）は、映像の開始時刻の扱いで最大 2 フレームずれる場合がある（目的の位置が先頭から約 2.5 秒以内なら `-ss` なしで先頭から読むので、大きなずれは起きない）。
  個別デコードのフォールバックは、映像の開始オフセット・1fps 未満の動画を考慮しない。
